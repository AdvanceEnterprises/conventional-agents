# Implementation Plan

This plan defines the validation strategy for implementing PLAN-0004 (markdownlint integration for ADRs). It maps each success criterion to concrete checks and sequences those checks across the rollout phases. The goal is to verify scope compliance, correct wiring, and clear contributor guidance without expanding linting beyond ADRs.

## Scope

- In: Validation of configuration parity, CI workflow wiring, local npm script behavior, ADR linting pass/fail behavior, and documentation updates.
- Out: Implementing linting itself, changing ADR content beyond lint fixes, or adding config drift detection.

## Implementation Steps

1. Define validation mapping for each success criterion in FS-0001 and each target test listed in CHANGE-PLAN-FS-0001 Section 3.
2. Specify exact file-level assertions for:
   - `docs/decisions/.markdownlint.yml` equals `vendor/madr/.markdownlint.yml`
   - `.github/workflows/lint-adrs.yml` uses `markdownlint-cli2-action@v17`
   - Workflow globs and path filters target only `docs/decisions/ADR-*.md` and `docs/decisions/.markdownlint.yml`
   - `package.json` includes `markdownlint-cli2` and `lint:adrs` script
3. Define local command validation steps for `npm install` and `npm run lint:adrs`.
4. Define CI behavior checks for failure on intentional ADR violation and success on remediation.
5. Specify documentation verification steps for `docs/decisions/README.md`.
6. Add one scope-boundary edge case: confirm `docs/decisions/README.md` is excluded from linting even when ADRs are linted.
7. Sequence tests by phase: Prepare, Enable CI, Validate/Monitor.

## Validation Tests

### Phase 1: Prepare (Pre-CI Enablement)

1. **test_sc_1__configuration_exists_and_matches_madr_baseline**
   - Verify `docs/decisions/.markdownlint.yml` exists without running any install commands.
   - Confirm it is an exact copy of `vendor/madr/.markdownlint.yml` (byte-for-byte).
   - Confirm only `MD013: false` and `MD024: false` are disabled and comments match MADR baseline.

2. **test_sc_3__npm_script_installs_and_runs**
   - Run `npm install`.
   - Run `npm run lint:adrs`.
   - Expect zero violations on existing ADRs after fixes (if any).

3. **test_sc_3__local_command_uses_correct_config**
   - Confirm `npm run lint:adrs` invokes `markdownlint-cli2 "docs/decisions/ADR-*.md"`.
   - Confirm CLI uses `docs/decisions/.markdownlint.yml` (same directory as targets).

4. **test_sc_5__all_existing_adrs_pass_linting**
   - Run `npx markdownlint-cli2 "docs/decisions/ADR-*.md"` (or via npm script).
   - Expect ADR-0000 through ADR-0009 to pass without warnings.

5. **test_sc_4__documentation_includes_setup_and_troubleshooting**
   - Verify `docs/decisions/README.md` includes:
     - Local setup instructions (npm install).
     - Local lint command (`npm run lint:adrs`).
     - Troubleshooting guidance with at least one concrete rule example.

### Phase 2: Enable CI

6. **test_sc_2__workflow_uses_correct_action_version_and_globs**
   - Verify `.github/workflows/lint-adrs.yml` uses `markdownlint-cli2-action@v17`.
   - Verify globs parameter is `docs/decisions/ADR-*.md`.
   - Verify triggers include only branch `trunk` and path filters:
     - `docs/decisions/ADR-*.md`
     - `docs/decisions/.markdownlint.yml`

7. **test_sc_2__ci_workflow_fails_on_adr_violations**
   - Create a PR with a deliberate ADR lint violation.
   - Confirm CI fails with readable output including file path, line number, and rule.

8. **test_sc_2__ci_workflow_passes_on_compliant_adrs**
   - Fix the violation and push.
   - Confirm CI passes.

9. **test_sc_2__non_adr_files_excluded_from_linting**
   - Create a PR that modifies only `docs/decisions/README.md`.
   - Confirm lint workflow does not run (path filters prevent it).

### Phase 3: Validate and Monitor

10. **test_sc_4__documentation_supports_contributors**
    - Spot-check first 3-5 ADR PRs after enablement.
    - Confirm contributors can resolve violations using README guidance without extra instruction.

### Extra Edge Case (Approved)

11. **edge_case__exclude_non_adr_in_decisions_dir**
    - Ensure `docs/decisions/README.md` is never linted even when ADRs are present.
    - Validate by confirming lint output only references `ADR-*.md` files.

## Notes

- CI branch name is `trunk`.
- No config drift detection is included at this time.
