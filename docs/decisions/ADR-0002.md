# ADR-0002: Roles reference skills via convention and skills index

## Status

- Proposed

## Context and Problem Statement

agent-dev-kit introduces skills as portable markdown modules (ADR-0001). Roles must be able to reference skills in a way that:

- Avoids vendor lock-in to any specific tool feature.

- Avoids maintenance burden as the skill library grows.

- Preserves discoverability for humans and agents.

- Avoids "dependency hell" where a role becomes unusable unless a long list of exact skill files is loaded.

The core problem:

- If roles hardcode exhaustive lists of skill files, roles become stale every time a new skill is added or renamed.

- If roles reference nothing, users lose discoverability and consistency, and each project reinvents the mapping.

## Decision Drivers

- Maintainability.

- Tool neutrality.

- Submodule friendliness and stable paths.

- Discoverability.

- Low operational complexity.

- Backward compatibility.

## Considered Options

### Option A: Hardcode explicit skill file lists inside each role

- Each role includes a complete, explicit list of skill file paths (and possibly per-language variants).

### Option B: Convention only

- Roles reference a naming convention (for example, skills/{language}-testing/SKILL.md) and do not mention specific skills.

### Option C: Convention plus a canonical skills index

- Roles reference a naming convention for default selection.

- Roles link to vendor/agent-dev-kit/skills/index.md as the canonical catalog.

- Roles may include a short "common choices" list, explicitly labeled as non-exhaustive.

## Decision Outcome

Chosen option: Option C (Convention plus a canonical skills index).

Rationale:

- Minimizes maintenance burden by avoiding exhaustive lists in role files.

- Preserves discoverability via a single canonical catalog.

- Supports cross-tool usage because roles and skills remain plain markdown.

- Keeps roles "valid" even when only the role file is loaded, while enabling richer performance when relevant skills are also loaded.

### File system contract (stable paths)

- Skills live at: `vendor/agent-dev-kit/skills/{topic}/SKILL.md`

- Skills index lives at: vendor/agent-dev-kit/skills/index.md

- Roles live at: `vendor/agent-dev-kit/roles/{role}.md`

### Role referencing rules

- Roles MUST reference the skills index:

  - vendor/agent-dev-kit/skills/index.md

- Roles MUST specify a convention-based selection rule for skills when applicable.

  - Example convention: skills/{language}-testing/SKILL.md

- Roles MAY include a "Common choices" list.

  - The list MUST be explicitly labeled as non-exhaustive.

  - The list MUST not be framed as required dependencies.

- Roles MUST NOT include exhaustive enumerations of all skills across languages.

- Roles MUST NOT claim a role is unusable without loading a specific skill file.

### Naming and convention constraints

- Skills SHOULD follow a predictable topic naming scheme that fits convention-based lookup.

- If a skill is renamed, the skills index MUST record the rename and the preferred replacement.

## Consequences

### Positive

- Roles remain stable as the skill library grows.

- Discoverability is centralized and consistent.

- Projects and tools can load role and skill content as plain markdown without special support.

- Reduces duplicated mapping logic across roles.

### Negative

- Conventions require clear documentation and consistent naming.

- Some users may pick the wrong skill if they only follow convention and ignore the index.

- The skills index becomes a critical document that must stay accurate.

### Neutral

- Roles can still provide helpful examples without becoming brittle.

- Projects can override role defaults by choosing different skills in their root AGENTS.md.

Reversal path:

- If conventions prove too constraining, roles can be updated to reference the skills index only.

- If the skills index proves insufficient, we can add a lightweight tag system inside skills/index.md without changing role contracts.

## Validation

We will consider this decision successful if:

- Adding a new skill does not require updating any existing role files.

- Users can find the correct skill for a role and language using skills/index.md.

- Roles remain readable and actionable when loaded alone.

Measurable signals:

- A new skill can be added by updating only:

  - `skills/{topic}/SKILL.md`

  - skills/index.md

- Roles that list "common choices" remain under a small, fixed number (for example, 3 to 6 entries) and are explicitly non-exhaustive.

- A spot check shows no role contains an exhaustive cross-language skill list.

Review checkpoints:

- After adding 5 skills: confirm the convention still fits and the index remains usable.

- Quarterly: confirm roles have not drifted into hard dependency declarations.
