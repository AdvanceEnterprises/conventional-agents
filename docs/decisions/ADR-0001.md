ADR-0001: Incorporate cross-tool portable skills as SKILL.md

Status
	•	Proposed

Context and Problem Statement

agent-dev-kit defines universal quality gates, guidelines, and role contracts intended to work across multiple AI coding tools (Claude Code, Codex, Aider, Cursor, and local models).

Claude Code provides native support for “skills,” but most other tools do not have a formal skills system. We want to incorporate skill-like capability modules without creating Claude-only lock-in or fragile, tool-specific coupling.

We need a way to:
	•	Provide deep, procedural expertise (examples, patterns, playbooks) in reusable modules.
	•	Keep universal gates canonical and avoid drift or duplication.
	•	Preserve portability and submodule friendliness using the mount path vendor/agent-dev-kit/.
	•	Avoid tool command recipes that become stale.

Decision Drivers

Key factors influencing the decision:
	•	Tool neutrality (Claude Code skills support exists; others treat files as context)
	•	Portability and submodule friendliness (stable paths under vendor/agent-dev-kit/)
	•	Discoverability (humans and tools should find the right content quickly)
	•	Drift control (avoid duplicating universal gates in many places)
	•	Operational usefulness (a skill file should be helpful even when loaded alone)
	•	Maintenance cost (minimize cross-file update requirements)

Considered Options

Option A: Claude-native skills only

Use Anthropic’s skills mechanism exclusively, relying on Claude Code’s native loader.

Option B: No skills, only roles and guidelines

Keep the system to role cards and guideline documents; do not create skill modules.

Option C: Portable markdown skills using SKILL.md

Create skills as self-contained markdown modules in skills/<topic>/SKILL.md.
	•	Claude Code can use these as skills.
	•	Other tools can load the same files as plain markdown context.

Decision Outcome

Chosen option: Option C (Portable markdown skills using SKILL.md).

Rationale:
	•	Preserves tool neutrality: the same file works whether a tool supports “skills” or not.
	•	Keeps skills useful on their own: a skill can include procedures and runnable examples.
	•	Avoids gate duplication: skills reference canonical gates in roles/ROLE_CONTRACT.md and the relevant guideline docs.
	•	Maintains stable, submodule-friendly paths under vendor/agent-dev-kit/.

File system contract (stable paths)

These paths are the stable integration surface for this decision:
	•	Skills live at: vendor/agent-dev-kit/skills/<topic>/SKILL.md
	•	Skills index lives at: vendor/agent-dev-kit/skills/index.md
	•	Canonical universal gates live at: vendor/agent-dev-kit/roles/ROLE_CONTRACT.md
	•	Canonical standards live at: vendor/agent-dev-kit/guidelines/*.md
	•	Tool-specific loading documentation lives at: vendor/agent-dev-kit/INTEGRATION.md

	•	Tool-specific loading documentation lives at: vendor/agent-dev-kit/INTEGRATION.md

Skill content rules

To prevent dependency hell while avoiding drift:
	•	Skills MUST be standalone-useful (include operational procedures, patterns, and runnable examples).
	•	Skills MUST be compliance-aware:
	•	Include a short, clearly labeled summary of key gates (non-exhaustive).
	•	Link to canonical sources:
	•	vendor/agent-dev-kit/roles/ROLE_CONTRACT.md
	•	Relevant vendor/agent-dev-kit/guidelines/*.md
	•	Use “For full compliance, also load…” language rather than “required references.”
	•	Skills MUST NOT duplicate the full universal gate list.
	•	Skills MUST avoid tool version specific command recipes.

Minimum content checklist for every skill

Each SKILL.md must include, at minimum:
	•	A brief “When to use this skill” section
	•	A “Compliance references” section with:
	•	Links to canonical sources
	•	A short, explicitly non-exhaustive summary of key gates
	•	At least 2 runnable examples
	•	A short, actionable checklist (copy-paste friendly)
	•	A “Common pitfalls” section

Relationship to roles

Roles define behavioral contracts and may recommend skills, but skills are not hard dependencies for non-skill-aware tools.

Roles should select skills via the skills index and conventions (for example, skills/{language}-testing/SKILL.md for language-specific testing), rather than hardcoding exhaustive lists.

Consequences

Positive
	•	A single skill artifact can serve Claude Code natively and still work for Codex, Aider, Cursor, and local models as context.
	•	Reduced vendor lock-in while still benefiting from Claude Code’s native features.
	•	Skills can carry rich procedural guidance without bloating roles or guidelines.
	•	Canonical gates remain centralized, reducing drift risk.

Negative

$1

Reversal path:
	•	If skills are deprecated, roles and guidelines remain authoritative.
	•	Skills become optional reference documents; the skills index should mark them deprecated.
	•	Update INTEGRATION.md to remove any skill-loading guidance; stable paths should be deprecated before removal.

Neutral
	•	Skills are “just markdown” to most tools; the loading mechanism varies by tool.
	•	Tool-specific loading instructions belong in INTEGRATION.md; optional helpers may live under packs/agent-config/.

Validation

We will consider this decision successful if:
	•	Adoption remains fast: a repo can add vendor/agent-dev-kit/ and gain useful skill guidance without tool-specific glue.
	•	A skill file provides immediate value when loaded alone (procedures/examples are sufficient to act).
	•	Drift is controlled: universal gates remain canonical in ROLE_CONTRACT.md, with skills only summarizing and referencing.
	•	Cross-tool usage is practical: projects can point any agent to the same skill file paths.

Measurable signals:
	•	At least one non-Claude workflow uses a skill file as plain markdown context successfully in an example repo (for example, Codex or a local model).
	•	No skill duplicates the full universal gate list (spot-check by searching for the universal gate section headings).
	•	Skills remain a manageable size by default (for example, under ~400 lines) unless there is a documented reason.

Review checkpoints:
	•	After the first 2 to 3 skills ship: confirm the pattern holds and summaries remain non-exhaustive.
	•	Quarterly: confirm no skill has become a dumping ground for universal policy.
